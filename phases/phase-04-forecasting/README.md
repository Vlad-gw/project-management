> **Что именно прогнозируем:** срок **подготовки учебной Фазы 5**, а не срок программной разработки системы. Фаза 4 использует **12 учебных задач F5-01–F5-12**. В Фазе 5 отдельно планируются **22 работы P01–P22** по разработке ПО. Смешивать их нельзя.

## 1. Декомпозиция и трёхточечные оценки

В [GitHub Issues #34–45](https://github.com/Vlad-gw/project-management/issues?q=is%3Aissue+F5-) и [исходной таблице](artifacts/phase5_academic_tasks.csv) зафиксированы 12 задач учебной Фазы 5: анализ задания; WBS 22 работ; штат; потребность в ресурсах; зависимости; длительности; генератор расписания; 12 эвристик; случайные эвристики; отбор лучшего решения; перевод в 8/40; отчёт и контроль.

Для каждой задачи заданы **L, M, U** — оптимистическая, наиболее вероятная и пессимистическая *оценки в человеко-часах*. Суммы L/M/U по 12 задачам: **62 / 97 / 149 чел.-ч**. Это сценарные оценки для расчёта; они не являются фактическими часами, независимо полученными от каждого участника.

**Метод восстановления:** задачу относим к неделе её даты **фактического окончания из журнала**, а не по дате административного закрытия GitHub Issue (многие Issues закрыты пакетно). Так как исходные журналы не содержат часов по конкретным дням, суммарные часы каждой задачи **равномерно разнесены по календарным датам от начала до окончания**, после чего агрегированы по ISO-неделям. Это *реконструкция*, не наблюдавшийся недельный табель. Подробные значения — [weekly_history.csv](artifacts/weekly_history.csv). Не выдаём модельные числа за непосредственно измеренные часы.

## 3. Модель 1 — случайная недельная скорость завершения задач

Эмпирическое дискретное распределение: **[8, 4, 0, 8, 8, 3] задач/неделю** (каждая из шести недель выбирается с равной вероятностью 1/6). В каждом независимом прогоне:
1. Генерируем количество завершённых за неделю задач выборкой с возвращением из истории.
2. Прибавляем к накопленному числу завершённых работ.
3. Повторяем до достижения **12 задач**. Нулевые недели учитываем как отсутствие прогресса.
4. Запоминаем количество затраченных недель.

## 4. Модель 2 — треугольная трудоёмкость + недельная доступность

1. Для каждой учебной задачи F5-01–F5-12 генерируем независимое значение **Triangular(Lᵢ, Mᵢ, Uᵢ)** в чел.-ч. Сумма = требуемая трудоёмкость учебной Фазы 5.
2. В каждой неделе генерируем случайную доступность из дискретного распределения восстановленных фактических часов **[12,4; 6,1; 0; 30,75; 89,583; 19,167] чел.-ч**.
3. Накопленные часы сравниваем с требуемой трудоёмкостью, пока не достигнем её. Для этой укрупнённой модели часы учебных задач условно считаются делимыми. Зависимости между учебными задачами *здесь* не моделируются.

## 5. Итог 120 000 итераций Монте-Карло

Генераторы фиксированы: **seed = 20261112** (вторая модель seed + 1). P80 = минимальное целое число недель, для которого эмпирическая вероятность завершения **не меньше 80%**.

| Показатель | Модель 1: задачи | Модель 2: чел.-ч |
|---|---:|---:|
| **P80** | **4 недели** | **7 недель** |
| Средняя длительность | 2,943 недели | 4,986 недели |
| Медиана | 3 недели | 4 недели |
| Вероятность завершить за 4 недели | 91,67% | 50,11% |
| Вероятность завершить за 7 недель | 99,84% | 83,34% |

**Разница: 3 недели.** Причины: модель 1 одинаково взвешивает малые и крупные работы, модель 2 учитывает трудоёмкость и неоднородный разброс доступных часов; историческая выборка короткая и содержит нулевую неделю. В модели 2 величины зависят от принятого способа реконструкции недельных часов.

Важно: **«80%» — прогнозная вероятность в каждой принятой модели, а не гарантия и не доверительный интервал для неизвестного истинного срока**. Более осторожный учебный ориентир — **7 недель**, с обязательным уточнением по реальным недельным табелям и подтверждённым тройкам оценок.
