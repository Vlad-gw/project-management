# Фаза 4 — Прогнозирование выполнения Фазы 5

**Статус: расчётная модель подготовлена; фактическая недельная статистика часов пока отсутствует.**

## Основание и предмет прогноза

В соответствии с заданием Фаза 4 прогнозирует продолжительность **учебной работы по Фазе 5**, а не срок разработки всего программного продукта. Для учебной Фазы 5 выделено **12 задач F5-01–F5-12** с трёхточечными оценками (L, M, U). Отдельно подготовлен черновик **22 работ P01–P22** по созданию системы аренды автомобилей — для собственно календарно-ресурсного планирования в Фазе 5.

## Источники и метод

**Метод 1 — дискретная скорость задач.** В качестве наблюдаемой величины взято число задач, закрытых в GitHub за каждую полную неделю до 02.11.2026: **[0, 12, 0, 0, 0]**. Это реальные даты *административных закрытий* Issues, но не восстановленная история фактической работы. Пакетное закрытие искажает скорость команды.

**Метод 2 — трудозатраты.** Для каждой из 12 задач используется треугольное распределение Triangular(L, M, U). Недельная доступность взята из **условного сценария** [18, 22, 26, 20, 24] чел.-ч, потому что достоверный недельный таймшит в репозитории отсутствует. Эти числа **не являются фактически отработанными часами**.

Прогон: **60 000 итераций**, фиксированный seed **20261102**, 80-й процентиль числа недель.

| Модель | P80 | Среднее время |
|---|---:|---:|
| 1. Число закрытых задач | **8 недель** | около 5 недель |
| 2. Треугольные часы и доступность | **5 недель** | около 5 недель |

Расхождение — **3 недели**, главным образом из-за пакетного закрытия GitHub Issues и разных определений скорости.

## Принципиальное ограничение

Для окончательной защиты как **эмпирического** прогноза необходимо заменить условный ряд недельных человеко-часов реальными данными. Также желательно восстановить реальные недели завершения задач, поскольку GitHub-статусы выставлялись пакетно. Пока P80 — только квантили соответствующих условных моделей.
