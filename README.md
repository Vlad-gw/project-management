## 1️⃣ Фаза 1 — Выбор концепции проекта

### Цель

Выбрать компактную концепцию программного проекта для дальнейшей работы.

### Рассмотренные альтернативы

- **A1** — система аренды автомобилей;
- **A2** — информационная система автосервиса;
- **A3** — система учёта и анализа личных финансов;
- **A4** — система управления фитнес-клубом.

### Методы выбора

- экспертное оценивание четырьмя участниками;
- трёхточечные оценки `(L; M; U)`;
- нечёткий коллективный **TOPSIS**;
- чёткий коллективный **МАИ**;
- проверка согласованности матриц МАИ;
- сопоставление результатов двух методов.

### Итог

Оба метода дали одинаковый порядок: **A1 > A2 > A3 > A4**.

| Метод | Результат для A1 | Место |
|---|---:|---:|
| TOPSIS | **CC = 0,7401** | **1** |
| МАИ | **0,2976** | **1** |

Для дальнейшей работы выбрана **система аренды автомобилей**.

## 2️⃣ Фаза 2 — Распределение работы

### Цель

Обоснованно распределить между четырьмя участниками задачи **Фазы 3**, учитывая трудоёмкость и индивидуальные предпочтения.

### Исходные данные

- **12 задач**, подготовленных на основе содержания Фазы 3;
- оценки плановых трудозатрат — всего **138 чел.-ч**;
- предпочтения четырёх участников по шкале **1–5**;
- доступные лимиты времени: **40 / 36 / 32 / 40 часов**.

### Метод распределения

- бинарные переменные назначения задач исполнителям;
- целевая функция — **максимум суммарной предпочтительности**;
- ограничения: каждая задача назначается ровно одному исполнителю, никто не превышает лимит, у каждого не менее двух задач;
- решение целочисленной задачи в **Python / SciPy (HiGHS)**.

## 3️⃣ Фаза 3 — Оценка проекта

### Цель

Оценить функциональный размер и трудоёмкость разработки системы аренды автомобилей, определить ориентировочные сроки, состав команды и необязательные для первой версии функции.

### Что оценивали

- **15 Use Cases** с основными, альтернативными и негативными сценариями;
- функции клиента и администратора, включая поиск, бронирование, оплату и управление автопарком;
- технические и средовые факторы, трудозатраты и ограничения.

### Методы оценки

- **COSMIC Function Points:** учёт движений данных Entry / Exit / Read / Write;
- **Use Case Points:** сложность акторов и Use Cases, коэффициенты TCF и ECF;
- **коллективная экспертная оценка:** согласование трудозатрат по Use Cases;
- сопоставление полученных оценок.

### Итог

| Метод | Размер | Оценка трудозатрат |
|---|---:|---:|
| COSMIC | **108 CFP** | **3 024 чел.-ч** |
| Use Case Points | **161,23 UCP** | **≈3 225 чел.-ч** |
| Экспертная оценка | 15 UC | **2 655 чел.-ч** |

Согласованная интегральная оценка — **около 2 983 чел.-ч** на *разработку программного продукта*. Для ориентировочного сценария с командой из четырёх специалистов — **около 29 недель** с резервом 15%. Гибкие тарифы и расширенные отчёты можно перенести в более позднюю версию.
